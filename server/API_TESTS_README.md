# API Tests Setup and Usage Guide

## Підготовка до запуску тестів

### 1. Налаштування тестової бази даних

**Windows:**
```bash
cd server
scripts/setupTestDb.bat
```

**Linux/Mac:**
```bash
cd server
chmod +x scripts/setupTestDb.sh
./scripts/setupTestDb.sh
```

### 2. Встановлення залежностей
```bash
npm install
```

### 3. Налаштування змінних середовища

Створіть файл `.env.test` у папці `server/` з наступним вмістом:
```env
NODE_ENV=test
TEST_DB_HOST=localhost
TEST_DB_PORT=5432
TEST_DB_USER=postgres
TEST_DB_PASSWORD=your_password
TEST_DB_NAME=nd_hw19_test
JWT_SECRET=test-secret-key-for-api-tests
```

## Запуск тестів

### Всі тести
```bash
npm test
```

### Окремі групи тестів

**Основні API тести:**
```bash
npm run test:api
```

**Тести аутентифікації:**
```bash
npm run test:auth
```

**Тести валідації даних:**
```bash
npm run test:validation
```

**Тести інтеграції з базою даних:**
```bash
npm run test:database
```

### Тести в режимі спостереження
```bash
npm run test:watch
```

### Тести з покриттям коду
```bash
npm run test:coverage
```

## Структура тестів

### 1. **api.test.ts** - Основні API тести
- GET /api/newsposts - отримання списку постів
- GET /api/newsposts/:id - отримання окремого поста
- POST /api/newsposts - створення поста
- PUT /api/newsposts/:id - оновлення поста
- DELETE /api/newsposts/:id - видалення поста
- GET /api/newsposts/categories - отримання категорій

### 2. **auth.test.ts** - Тести аутентифікації та авторизації
- Перевірка захищених endpoint'ів
- Валідація JWT токенів
- Тести з недійсними/прострочених токенами
- Тести опціональної аутентифікації

### 3. **validation.test.ts** - Тести валідації даних
- Валідація обов'язкових полів
- Перевірка довжини полів
- Обробка спеціальних символів
- Валідація параметрів запиту
- Обробка некоректного JSON

### 4. **database.test.ts** - Тести інтеграції з базою даних
- Перевірка збереження даних
- Перевірка оновлення записів
- Перевірка видалення записів
- Тести цілісності даних
- Тести пагінації та фільтрації
- Обробка помилок бази даних

## Технічні особливості

### База даних
- Тести використовують окрему тестову базу даних
- База очищається після кожного тесту (afterEach)
- Схема створюється автоматично (synchronize: true)
- dropSchema: true - видаляє схему при підключенні

### Аутентифікація
- Використовується реальний JWT для тестів
- Створюються тестові користувачі для кожної групи тестів
- Тестуються різні сценарії з токенами

### Суперtest
- Усі запити до API виконуються через supertest
- Перевіряються як статус-коди, так і тіло відповіді
- Додаткова перевірка в базі даних після операцій

## Вимоги до системи

- Node.js 18+
- PostgreSQL 12+
- npm або yarn

## Рекомендації

1. **Запускайте тести в ізольованому середовищі** - використовуйте окрему тестову базу
2. **Очищайте дані** - тести самостійно очищають базу після виконання
3. **Перевіряйте покриття** - використовуйте `npm run test:coverage` для аналізу покриття коду
4. **Документуйте нові тести** - додавайте описи до нових тестових сценаріїв

## Troubleshooting

### База даних не підключається
- Перевірте чи запущений PostgreSQL
- Перевірте правильність креденшалів
- Переконайтеся що тестова база створена

### Тести падають через timeout
- Збільште timeout в jest.config.js (testTimeout: 30000)
- Перевірте швидкість підключення до бази

### Помилки JWT
- Перевірте що JWT_SECRET встановлений
- Переконайтеся що токени генеруються правильно

### Проблеми з TypeScript
- Запустіть `npm run build` для перевірки компіляції
- Перевірте типи в entities та interfaces
